# Audit — 2026-10-30

Scope: `vezeqs/git-forensics` (skills, tools, tests, docs, README, AGENTS.md)
plus the `crit-code` skill and the global rules that invoked it.

Baseline before any change:

```
$ make check
Ran 57 tests in 9.349s
OK
```

History read: `5727671` parse the bisect verdict on git 2.55 and later,
`ff37ce1` print the report when a hunt assertion fails, `b425599` prepare
0.1.0. Pull requests: **none** — `gh pr list --state all` returns an empty
array, so all changes landed directly on `main` and there is no PR context to
read.

Severity scale: Blocker, High, Medium, Low, Nit. Nothing here is a Blocker or
High; the tool's core behaviour is sound. The findings are in the output
contract and the build path.

---

## F1 — README advertises the wrong test count (Medium)

**Claim:** `make check` runs "validator + 51 tests".
**Evidence:** `python3 -m unittest discover -s tests` reports `Ran 57 tests`.
The count went stale when six parser and validator tests were added in the
previous audit and nobody updated the README.
**Cause:** a number in prose that nothing checks.
**Fix:** state the count once and keep it out of the command comment, so it
cannot drift again.
**Status:** fixed. The README no longer states a count that can drift.

## F2 — `files_changed[].path` is not a path for non-ASCII filenames (Medium)

**Claim:** the JSON report lists the files a commit changed, with usable paths.
**Evidence:** git quotes paths by default (`core.quotePath=true`):

```
$ git show --numstat --format= HEAD
2	0	"caf\303\251.txt"
```

`commit_details` passes that through unchanged, so the JSON contains
`"caf\\303\\251.txt"` and `os.path.exists()` on it is false. Reproduced with a
file named `café.txt`; a tab in the name fails the same way.
**Cause:** parsing human-facing numstat output instead of the machine format.
**Fix:** read `--numstat -z`, which emits raw NUL-separated paths, and handle
the rename record (`added\tremoved\t\0old\0new\0`).
**Status:** fixed, `test_reports_non_ascii_paths_unquoted` and
`test_reports_a_rename_with_both_names`.

## F3 — `make assets` can leave `docs/` half-regenerated (Medium)

**Claim:** `docs/` is generated from a real run, so it always matches the code.
**Evidence:** with Pillow unavailable, `tools/render_assets.py` writes the three
SVGs first, then dies importing PIL for the GIF:

```
$ PYTHONPATH=/tmp/fakepil python3 tools/render_assets.py
ImportError: Pillow is not installed
$ ls -l docs/
-rw-r--r-- 1 ... 23:10 blame-archaeology.svg   # rewritten
-rw-r--r-- 1 ... 22:55 demo.gif                # stale
```

The failure is a raw traceback, and Pillow is not mentioned in the README or
the Makefile, so a contributor meets an unexplained dependency.
**Cause:** no dependency check, no staging, no atomic replace.
**Fix:** check Pillow up front with an actionable message, render into a
staging directory, and move files into `docs/` only after all four succeed.
Document the dependency.
**Status:** fixed. With Pillow blocked, `docs/` is untouched and the message
names the install command.

## F4 — Pillow is unpinned, so images are not reproducible (Low)

**Claim:** regenerating the images produces the same files.
**Evidence:** `make assets` uses whatever Pillow is installed; there is no
`requirements-dev.txt` and no pin. The GIF encoder is part of Pillow, so a
version change can alter bytes that are committed.
**Cause:** a build dependency that is not declared.
**Fix:** add `requirements-dev.txt` pinning Pillow, and reference it from the
README and AGENTS.md.
**Status:** fixed, `requirements-dev.txt` pins Pillow 11.1.0.

## F5 — A skill-name test can pass on prose (Low)

**Claim:** `test_every_skill_has_a_matching_directory_name` verifies that each
skill's frontmatter `name` equals its directory.
**Evidence:** it asserts `"name: <dir>" in text` over the whole file, so a
sentence or code block containing that string satisfies it even if the
frontmatter says something else.
**Cause:** substring check instead of parsing.
**Fix:** parse the frontmatter with the validator's own parser and compare the
field.
**Status:** fixed, `test_every_skill_frontmatter_name_matches_its_directory`
parses the frontmatter.

## F6 — `crit-code` tells the agent to rewrite a README that may be fine (Low)

**Claim (in the skill):** Phase 3 produces a README a stranger can skim.
**Evidence:** it says "Rewrite the README so a stranger gets it in thirty
seconds", unconditionally. That conflicts with the repository rule "do not
reformat files you were not asked to touch" and wastes a full rewrite on a
README that already passes.
**Cause:** a step written as an action instead of a test.
**Fix:** verify against a checklist first, rewrite only the parts that fail.
**Status:** fixed. Phase 3 now says to rewrite only what fails the checklist.

## F7 — `--keep` does not say where the worktree is when preflight fails (Low)

**Claim:** `--keep` leaves the worktree for inspection.
**Evidence:** when the preflight refuses, `hunt.py` exits 4 with the reason and
never prints the path. The kept worktree is in a random temp directory the user
cannot find without `git worktree list`.
**Cause:** the path is only reported in the success report.
**Fix:** print the worktree path to stderr as soon as it is created under
`--keep`.
**Status:** fixed, `test_keep_prints_the_worktree_path_when_preflight_fails`.

## Checked and not a bug

- **Tab in a filename** does not break the numstat parser: git quotes the tab,
  so the record stays on one line. The quoting itself is F2.
- **`git bisect start` on a dirty tree** proceeds when the dirty files are
  untouched by the range. The README says so; no change needed.
- **Permission-denied on a target file** exits 1 with the errno message. That
  is an environmental failure, not a usage error; leaving it.
- **Merge commits have an empty `files_changed`.** `git show --numstat` prints
  nothing for a merge without `-m`. Documented in AGENTS.md as expected.
